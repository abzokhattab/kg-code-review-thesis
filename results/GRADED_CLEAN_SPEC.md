# Pre-Registration Spec: Clean Graded-Scale Run

**Purpose:** Determine whether anchored 0-3 scoring reveals signal that binary 0/1 scoring
suppresses, in a way that is free of confounds and defensible at the viva.

---

## What is fixed before any data is collected

### 1. Generator
GPT-4o, temp=0.0, seed=42 — identical to the canonical main experiment.
Baseline reviews: already exist in `outputs/luca_prs_v2/pr*_baseline.md`.
Joern-KG reviews: already exist in `experiments/2026-05-15_joern_kg_main/exp_b_full35/pr*_review.md`
  BUT these were generated by Gemini 2.5 Flash with the strict prompt.
  **Requirement:** Re-generate the Joern-KG arm with GPT-4o before running graded scoring.
  This is the same job as `exp_gpt4o_joern.py` — blocked on OpenAI quota.

### 2. Judge panel
Same 3-judge panel as the main experiment: gpt-4o-mini, gpt-4o, gemini-2.5-flash.
Aggregation: mean score (not majority vote, since scores are now ordinal 0-3).
Inter-rater agreement: Spearman ρ between each judge pair, per criterion.

### 3. Prompt
**No mandatory coverage instructions.** The judge prompt states the anchored descriptors
and asks for a score 0-3. It does NOT tell the generator what to cover. The generator
prompt must be identical across baseline and Joern-KG arms.

### 4. Criteria — pre-declared, outcome-blind
Grade only the 6 canonical KG-relevant criteria: **C2, F3, F4, M1, T2, T3**.
(These are tagged kg_relevant=True in evaluate_reviews.py and have been the subscale
throughout the project.)

Do NOT include P1 or R2 — both are kg_relevant=False. Including them was the post-hoc
gerrymandering problem in the exploratory run.

Anchored descriptors must be written and frozen before scoring begins.
Criterion-level dropping (e.g., "P1 is mechanistically null") is only permissible if
declared here, before seeing any scores.

**Pre-declared exclusion:** None. All 6 criteria are scored. If a criterion shows
Δ≈0, that is a finding ("Joern does not help with X"), not a reason to drop it.

### 5. PR set
All 35 non-Go PRs (exclude PR9, 27, 35, 36, 37 — Joern Go frontend limitation).
No further filtering. KG-rich (n_tests>0 OR n_deps>2) is reported as a moderation
analysis, not used as the primary sample.

### 6. Comparison reported
Side-by-side, same PRs, same criteria:
- Binary d_z (existing, from `exp_b_full35`) — n=35
- Graded d_z (new run) — n=35
Both numbers computed on identical (pr_id, mode) pairs.

---

## What the result answers

> Does replacing binary 0/1 judgment with anchored 0-3 scoring increase the
> measured effect size of Joern context, on the same PRs, same criteria, same
> judge panel?

If graded d_z > binary d_z: ceiling effect was real, graded scoring is the better
instrument. Thesis claim: "binary scoring underestimates the effect."

If graded d_z ≈ binary d_z: ceiling effect is not the bottleneck. Binary scoring
is adequate. Thesis claim: "graded scoring confirms binary result."

Either outcome is defensible. Neither requires cherry-picking.

## Blocker

`exp_gpt4o_joern.py` requires OpenAI credits (GPT-4o, 35 PRs × ~$0.10 = ~$3.50).
Once credits are topped up, the run order is:
1. Run `exp_gpt4o_joern.py` → generates GPT-4o + Joern reviews in `exp_gpt4o_joern/`
2. Run `evaluate_reviews_graded.py --joern-dir experiments/.../exp_gpt4o_joern \
     --judges openai:gpt-4o-mini,openai:gpt-4o,gemini:gemini-2.5-flash \
     --joern-mode-label gpt4o_joern`
3. Report binary vs graded side-by-side on n=35.

Estimated total cost: ~$5 (generation) + ~$1 (graded judging) = ~$6.
Estimated wall-clock: ~30 minutes.
Idempotent: yes (both scripts skip cached outputs).
