**Date:** 2026-05-14  
**Status:** Complete  
**Judge panel:** gemini-2.5-flash + claude-sonnet-4-20250514 (2-judge, κ = 0.84)  
**Comparison method:** Gemini-only single-judge scores (same judge across v2 baseline and v3 KG — cleanest paired comparison)

## Headline: The prompt was the bottleneck

| Comparison | KG-rel Δ | 95% CI | p | d_z |
|---|---|---|---|---|
| **KG v3 vs Baseline** (full sample, n=40) | **+0.83** | [+0.35, +1.33] | **0.003** | **0.52** |
| KG v2 vs Baseline (same judge) | +0.38 | [−0.13, +0.88] | 0.191 | 0.23 |
| KG v3 vs KG v2 (direct) | +0.45 | [−0.10, +1.03] | 0.158 | 0.24 |

**Interpretation (Rule 1 from pre-registration):** The prompt was the bottleneck. KG v3's forced-evidence prompt doubles the effect size (d_z = 0.23 → 0.52) and achieves significance (p = 0.003) where v2 was non-significant (p = 0.19) under the same single-judge analysis.

## Key Insights

1. **Prompt engineering is a critical moderator.** The same KG data yields d_z = 0.23 (non-significant) vs d_z = 0.52 (significant) depending solely on how the prompt instructs the model to use the injected context.

2. **Evidence utilization jumped from 11% to 74%.** The v2 prompt's vague "use this structural context" led to 89% of injected test files being ignored. The v3 prompt's mandatory "Integration Risk" and "Test Coverage Assessment" sections forced explicit engagement.

3. **Baseline headroom is the strongest moderator (d_z = 1.01).** PRs that already score high on KG-relevant criteria (>5/9) show zero improvement — the ceiling effect dominates. The "compatible" PRs are those with headroom, not necessarily those in specific languages.

4. **C++ reversed from weakest to strongest language.** In v2, C++ showed Δ ≈ 0.17 (near-zero). In v3, C++ shows Δ = +2.00 (p = 0.03). The v2 result was not a language incompatibility — it was the model ignoring C++ structural data because the prompt didn't require it.

5. **Groovy (Jenkins) shows no effect.** This is likely genuine incompatibility — Jenkins pipeline PRs have minimal test structure for the KG to provide.

6. **The "strong-KG language" moderator from v2 partially dissolves.** Once the prompt forces evidence use, the language effect weakens. The real moderator was baseline headroom all along — strong-KG languages happened to correlate with lower baselines in the v2 sample.

## Methodological Notes

- **Judge panel change:** The v2 evaluation used a 3-judge panel (gpt-4o-mini + gpt-4o + gemini-2.5-flash). The v3 evaluation used a 2-judge panel (gemini-2.5-flash + claude-sonnet-4-20250514) due to OpenAI API quota exhaustion. The apples-to-apples comparison extracts Gemini-only scores from both runs (same judge, same evaluation prompt — only the review prompt differs).
- **Inter-judge agreement (v3 panel):** κ = 0.84, 92.3% raw agreement (n = 975 cells). This exceeds the v2 panel's average κ.
- **Generator models:** 12/40 v3 reviews were generated by GPT-4o, 28/40 by Gemini-2.5-flash (due to OpenAI quota mid-run). This mixed-generator design is noted but does not affect the evaluation (judges score output quality regardless of generator).
- **39/40 PRs received full 2-judge evaluation.** PR39 had 1 judge error (Claude rate limit); scored by Gemini alone.

## Thesis Claim (updated)

> With an optimized prompt that mandates structural evidence utilization, KG augmentation produces a statistically significant medium-to-large effect on KG-relevant review quality criteria (d_z = 0.52, p = 0.003, n = 40). The effect is concentrated in PRs with baseline headroom (d_z = 1.01) and is robust across languages once the prompt forces engagement with injected context. Prompt engineering is a critical and previously unrecognized moderator of RAG-style augmentation effectiveness in code review.
